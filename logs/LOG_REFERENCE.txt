LOG SYMBOLS
═══════════
  [OK]  Success/Complete      Example: SUCCESS: Camera opened and configured
  [FAIL]  Failure/Error         Example: FAILED: Open camera 640x480
  [WARN]  Warning/Slow (>1s)    Example: SLOW DONE: Initialize ... | Time: 5.23s
  [TIME]  Timing Info           Example: DONE: Process frame | Time: 0.033s
  ->  Entering State        Example: Entering PLAY MODE | level=letters
  <-  Exiting/Returning     Example: Play mode action: menu

LOG LEVELS
══════════
  DEBUG    (File only)     Frame-by-frame details, resize events
  INFO     (Console+File)  Normal flow, state changes, success messages
  WARNING  (Console+File)  Slow operations, recoverable errors
  ERROR    (Console+File)  Component failures, exceptions
  CRITICAL (Console+File)  System-level crashes

WHAT TO LOOK FOR WHEN SOMETHING IS BROKEN
═════════════════════════════════════════════

1. Search for "[FAIL]" or "ERROR"
   These mark actual failures. First ERROR is usually the root cause.

2. Search for "[WARN]" (warnings)  
   Times > 1s indicate slow loading or processing.

3. Search for specific component names:
   - HandTracker    - Hand detection issues
   - FaceTracker    - Face detection issues  
   - Classifier     - ASL sign classification issues
   - Overlay        - Display/rendering issues
   - Camera         - Webcam initialization issues

COMMON ERROR PATTERNS
═════════════════════

Empty hand detections?
  -> Look for: "Frame X | FPS: X" entries
  -> If you see FPS drops, processing is slow

App won't start?
  -> Look for earliest ERROR message
  -> Usually: Camera, HandTracker, or FaceTracker initialization

Signs not recognized?
  -> Look for Classifier errors in log
  -> Check FPS - if too low, might be affecting recognition

DEBUGGING WORKFLOW
══════════════════

1. Run: python main.py
2. Do your action (play, debug, etc.)
3. Press ESC to exit
4. Open logs/signsense_*.log (most recent)
5. Search for patterns:
   - First "ERROR" -> root cause
   - "[WARN]" entries -> slow operations
   - "Frame X | FPS" -> processing speed
   - Component name + "Error" -> specific failure
6. Look at PERFORMANCE REPORT at end for statistics

PERFORMANCE REPORT MEANINGS
═════════════════════════════

Count      - How many times this operation ran
Avg        - Average time per operation (in seconds)
Min/Max    - Fastest and slowest times
Good times:
  - Open camera:           < 0.1s
  - Initialize detectors:  < 2s (can be 3-5s on first load)
  - Process frame:         < 0.033s (for 30 FPS)
  - Render overlay:        < 0.01s

Bad times:
  - Any > 5s = very slow
  - Any frame > 0.1s = drops FPS
  - Recurring errors = pattern issue


QUICK POWERSHELL COMMANDS
═════════════════════════

# Show last 100 lines
Get-Content logs/signsense_*.log | Select-Object -Last 100

# Find all errors
Get-Content logs/signsense_*.log | Select-String "ERROR|FAILED"

# Find all warnings
Get-Content logs/signsense_*.log | Select-String "[WARN]|WARNING"

# Show performance report only
Get-Content logs/signsense_*.log | Select-String -Pattern "^[^|]*\|.*PERFORMANCE|^[^|]*\|.*Timing Statistics:|^[^|]*\|.*Count:" -Context 1

# Find specific component errors
Get-Content logs/signsense_*.log | Select-String "Classifier|HandTracker|FaceTracker"

# Count total frames processed
(Get-Content logs/signsense_*.log | Select-String "Frame [0-9]+").Count
